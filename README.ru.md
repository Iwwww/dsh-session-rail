# dsh-session-rail

Переключатель чатов в рейле для веб-клиента [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): одна иконка под кнопкой **New session** открывает флайаут с поиском по вашим проектам и их последним сессиям, так что переключать чаты можно не разворачивая сайдбар.

![Флайаут с раскрытым текущим проектом](docs/flyout.png)

Свёрнутый рейл становится таким: логотип, **New session**, **Search**, **Chats**, затем прижатый к низу блок.

![Свёрнутый рейл](docs/rail.png)

## Что он делает

- **Текущий проект раскрыт по умолчанию.** Открыт всегда ровно один проект: наведение на другой меняет его местами, клик по открытому — сворачивает.
- **Высота окна фиксируется при открытии**, поэтому переключение проектов прокручивается внутри стабильной рамки, а не уводит край окна из-под курсора.
- **Закрывается только при явном уходе** — дальше 24 px от строки и окна и дольше 420 мс; закрытие анимировано, возврат курсора его отменяет.
- **Строки несут те же статусы, что и сайдбар**: ждёт ответа, выполняется, завершено, и метка активной задачи по расписанию.
- **Поиск использует хостовый индекс содержимого** вместе с локальным совпадением по заголовкам, со сниппетами, дебаунсом и отменой предыдущего запроса — как в самом сайдбаре.
- **На строке проекта есть «новый чат в этом проекте»**, а на строке чата по наведению — форк, переименование и архивация.
- **Это `tree`**: стрелки перемещают, Enter активирует, Escape закрывает, а из поля поиска ArrowDown переводит фокус в список.
- Строка существует **только когда рейл свёрнут**. Развёрнутый сайдбар остаётся стандартным, вместе с действием **Add workspace**.

Скрытые в сайдбаре сессии скрыты и здесь: субагентские, архивные и промежуточная пустая строка New session.

## Установка

```sh
dsh plugin --profile web add dsh-session-rail
```

Пакет несёт собственный bundle-патч, поэтому команда сразу добавляет его в стек слоёв профиля — править `cordis.patch.yml` не нужно. После установки перезагрузите страницу: граф загрузки браузера собирается в момент отдачи страницы.

Удаление:

```sh
dsh plugin --profile web remove dsh-session-rail
```

## Полнотекстовый поиск в DSH выключен по умолчанию

Поставляемый профиль `web` конфигурирует индекс session-query как `openAt: never`, что отключает полнотекстовый поиск во всём развёртывании — по этой же причине штатный поиск сайдбара пишет «Content search is temporarily unavailable». Плагин это умолчание не меняет. Чтобы в флайауте появились совпадения по содержимому и сниппеты, включите индекс в патче профиля (`~/.dsh/profiles/web/cordis.patch.yml`):

```yaml
- id: session-query-sqlite
  config:
    path: ':memory:'
    openAt: first-search
```

Без этого флайаут продолжит фильтровать по именам сессий и проектов и сообщит, что поиск по содержимому недоступен.

## Требования

- DeepSeek Harness `0.1.5-rc.1` или `0.1.6-alpha.1` (обе версии проверены целиком).
- Node 22 или новее — для самого CLI `dsh`.
- Никаких runtime-зависимостей: браузерная половина — один рукописный client-module бандл, которому нужны только платформенные модули (`react`, `react-dom`, `@deepseek-ai/dsh-client-ui-primitives`).

## Настройка

Всё живёт в константах над стилями в `lib/client.js`:

| Константа | По умолчанию | Значение |
|---|---:|---|
| `MAX_PROJECTS` | 6 | Проектов до строки «ещё проекты» |
| `MAX_CHATS` | 5 | Сессий на проект до строки «ещё» |
| `MAX_CHATS_EXPANDED` | 25 | Сессий после нажатия этой строки или при поиске |
| `HOVER_OPEN_MS` | 160 | Задержка открытия по наведению |
| `HOVER_CLOSE_MS` | 420 | Грейс-период перед закрытием |
| `CLOSE_MARGIN` | 24 | Насколько далеко от строки и окна ещё считается «внутри» |
| `SEARCH_DEBOUNCE_MS` | 250 | Дебаунс перед хостовым поиском по содержимому |

## Как это устроено

- Строка регистрируется в `sidebar.panellist` — списке иконок глобальных панелей, который оболочка рендерит сразу под **New session**, — и только пока присутствует `[data-sidebar-collapsed]`. Поэтому развёрнутый сайдбар остаётся ровно таким, каким его отгружает DSH.
- Оболочка рендерит этот список **до** области воркспейсов, поэтому нужный порядок (Search выше Chats) — это перестановка flex-`order`: область перестаёт растягиваться, низ забирает свободное место, а строка встаёт между ними. Строка заголовка области, в которой живёт **Add workspace**, в рейле скрывается.
- Кнопка строки принадлежит оболочке и на клик вызывает `selectPanel`, поэтому плагин забирает её нативным слушателем, который срабатывает раньше React-диспетчеризации. Полноширинная панель `main` остаётся зарегистрированной только чтобы ничто не могло бросить исключение.
- Всё находится структурно (`data-slot`, порядок соседей, группа действий, не содержащая кнопку Search), а не по именам классов или локализованным подписям; все правки рейла снимаются при разворачивании. Перетасованная оболочка деградирует к стандартному порядку, а не ломается.

## Разработка

Инструментам нужны бинарь `dsh` (`DSH_BIN`, по умолчанию `dsh`), CLI `zstd`, `playwright-core` (`PLAYWRIGHT_CORE`) и Chromium (`CHROMIUM`, по умолчанию `/usr/bin/chromium`).

```sh
npm run check       # парсит все исходники, проверяет манифест и словари
node tools/smoke.mjs       # браузерный набор против вымышленного DSH_HOME
node tools/screenshots.mjs # пересобирает docs/*.png и падает при утечке реальных данных
```

`tools/fixture-home.mjs` собирает вымышленный home, которым пользуются последние две команды: три придуманных воркспейса (`acme-web`, `orion-api`, `design-system`), сессии которых генерирует `dsh --profile headless` по придуманным промптам, а затем переименовываются и раскладываются по правдоподобной истории. Мутирующие проверки (форк, переименование, архивация, новая сессия) выполняются только там и никогда — в вашем `DSH_HOME`.
